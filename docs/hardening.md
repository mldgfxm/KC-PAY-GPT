# 支付任务与敏感数据加固

## 权限与接口兼容

- `/api/admin/data` 不再返回卡号、有效期、CVC，卡片数量改为 `config.card_pool_count`。
- 卡池、Session、CDK、含完整卡号的账单接口，以及通过旧配置接口修改卡池，均要求管理员令牌和有效的 `X-Admin-Secondary-Token`。
- 后台在访问敏感功能时弹出密码输入框；二级令牌仅在当前页面内存保存，默认 30 分钟有效。修改二级密码会立即使旧令牌失效。
- `/api/run-process` 创建任务及 `/api/verify-cdk` 恢复任务时增加 `taskToken`。WebSocket 的订阅消息必须携带 `{type: 'subscribe', jobKey, taskToken}`；管理端可以携带 `adminToken`。
- 旧前端只提交任务号将被拒绝。部署后需要刷新前端；24 小时任务令牌过期后，通过原 CDK 重新验证运行中的任务取得新令牌。
- 任务签名密钥保存在持久化的 `data/task-access.secret`，不是通过工作目录推导的可预测值。`TASK_ACCESS_SECRET` 仅用于需要显式管理密钥的环境及测试。

## 已支付事实、并发与任务终态

新任务通过短事务锁定并发配置记录，同时完成全局容量检查、账号/CDK 占用和任务创建，兼容同库多进程。
账号优先使用 Session 中的 account ID，缺失时使用邮箱；两者都缺失则拒绝启动，不能用不同 AccessToken 绕过账号互斥。

`activation_claims` 保存任务占用，每 15 秒由执行进程续租，租约为 120 秒。成功任务遗留的占用会在下一次准入时清理。
非成功任务若因进程崩溃留下占用，不会自动退款或再次支付：租约过期后不占全局名额，但账号/CDK 仍保持保护，需要核实该任务结果后处理。

子进程确认支付成功后，先通过 IPC 报告支付事实；数据库或本地记账故障只能形成补偿任务，不能返回“未支付”并再次扣款。
支付事件先写入持久化 `data/payment-outbox`，再以 `job_key` 幂等地更新 `payment_receipts`、用卡次数、账单及续费队列。
MySQL 暂时不可用时文件保留，后台恢复后只重放记账，不重新调用支付；账单仅保存卡号后四位。
磁盘暂不可写时会尝试直接写库。原执行进程不再续租后，后台会批量恢复有支付凭证、但终态未保存成功的订单。
本机磁盘与数据库同时不可写时无法承诺自动恢复，任务会保留已支付提示并要求管理员核实，不会主动重新扣款。

日志进度更新串行执行，并在 worker 返回前排空；数据库更新还限制任务从运行态进入终态，禁止迟到的 `running` 更新覆盖已完成状态。

## 续费补偿

`renewal_jobs` 持久化以下状态：`pending`、`running`、`retry`、`confirmed`、`manual`。
实时收尾与后台补偿使用同一条数据库租约，避免同时取消同一任务的续费。

- 后台每 15 秒检查一次队列，每次领取一条待处理任务。
- 失败按指数退避重试，间隔最高 1 小时；总计 8 次仍未确认转人工处理。
- Session 失效及 App Store/Google Play 订阅直接转人工处理，不无限重试。
- 只有查询明确返回自动续费关闭才标记 `confirmed`，接受取消请求但尚未确认会继续核实。
- 后台“续费管理 → 自动关闭续费补偿”可以查看状态，并重新排队。Session 过期时，在原有 Session 输入框粘贴同一账号的新 Session 后重新排队；禁止替换为其他账号。
- 查询 `GET /api/admin/renewal-jobs`；重新排队 `POST /api/admin/renewal-jobs/:jobKey/retry`，可选请求体 `{session}`，后者要求二级验证。

`COMPENSATION_ENABLED=0` 可在隔离测试或维护期间停止定时扫描；正常部署默认开启。
队列不自动收集历史订单，仅处理本版本之后确认支付并入队的任务。

## 数据迁移与批量操作

启动时增量创建三张保护表，并为 `card_assets.card_number` 添加唯一索引。迁移不会清空原数据。
若旧库已经有重复卡号，启动会明确报错并停止，不自动删除卡片或合并存在冲突的凭据。先备份，核实重复记录和占用状态后再处理。

导入卡片按 100 条分批写入，数据库唯一索引负责并发去重；不会在导入循环中逐张查询、逐张插入。
邮箱导入也按 100 条分批写入；配置默认值批量初始化，批量续费查询一次读取本批 Session 后再调用外部服务。
全量替换卡池配置时如果仍有被任务占用的卡片，会拒绝保存，避免删除正在使用的资产。

## 验证与部署

```powershell
npm test
```

测试排除 `.local/**`，不会重复执行本地发布副本的测试。
真实 MySQL 及浏览器验证使用 `scripts/test-hardening-db.cjs` 和 `scripts/test-hardening-browser.cjs`。
两者只创建随机命名的 `kc_hardening_test_*` 隔离库，完成后删除测试库；浏览器验证禁用补偿定时器，且仅使用合成账号和测试卡号，不发起真实支付或取消订阅请求。

部署前等待所有任务结束，备份数据库及 `data`，重新构建整个镜像后替换应用容器，不能只复制单个 JS 文件。
本地部署仍使用 `scripts/local-deploy.ps1 Update`；NAS 使用新镜像重新导出并导入，同时保留原数据目录及密码。
`payment-outbox`、`task-access.secret` 必须和数据库一起持久化及备份，不能纳入 Git 或 Docker 构建上下文。
